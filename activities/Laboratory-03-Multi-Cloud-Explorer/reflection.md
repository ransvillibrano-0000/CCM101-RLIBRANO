# Mission 3 Reflection

Exploring the multi-cloud ecosystem was an eye-opening experience. The cloud platform that 
impressed me the most was Google Cloud Platform (GCP). Coming from a background where I frequently 
configure my own native PHP projects, I found GCP’s heavy emphasis on open-source technologies, 
Kubernetes, and developer-friendly data analytics incredibly forward-thinking and modern.

Despite their differences, there are massive similarities among AWS, Azure, and GCP. At their core, 
they all utilize the exact same foundational service models—Infrastructure as a Service (IaaS), 
Platform as a Service (PaaS), and Software as a Service (SaaS). They all offer virtual machines, 
object storage, and managed databases, effectively solving the same problems but with different 
terminology and user interfaces. 

This mission highlighted how heavily business requirements influence platform selection. A cloud 
engineer cannot just pick their favorite provider; they must align the choice with the client's 
existing assets. For example, forcing an organization already reliant on Active Directory into 
AWS introduces unnecessary friction, making Azure the superior business choice.

Acting as a Cloud Solutions Consultant taught me the importance of vendor neutrality. I learned 
to analyze infrastructure not just as technical components, but as tools that solve distinct 
business constraints—whether that is budget limitations, AI processing needs, or global scalability. 

Finally, adding this comprehensive comparison to my GitHub Cloud Computing Portfolio has vastly improved 
its professional quality. As a 4th-year BSIT student preparing to enter the workforce, this repository 
now demonstrates my ability to not only write code and configure Linux servers, but to critically analyze 
enterprise infrastructure architecture, document it cleanly in Markdown, and utilize version control 
efficiently.
